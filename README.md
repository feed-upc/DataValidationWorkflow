# Data Validation Workflow Engine

This repository provides the core **Executor** and **Planner** engine for automating data quality validation in federated data spaces. It is designed to be used as a submodule within a larger governance architecture.

## Overview

The engine operates in two main phases:

### 1. Planning Phase (PLANNER)
- **Input**: Data Product Metadata (RDF) + Data Quality Policies (ODRL/JSON-LD).
- **Process**: Uses N3 logic rules to reason over the metadata and policies.
- **Output**: A **PolicyChecker** graph (validation plan) that details the required validation operations (`ab:CheckFreshness`, `ab:NonNullValues`, etc.).

### 2. Execution Phase (EXECUTOR)
- **Input**: The PolicyChecker graph generated by the Planner.
- **Process**: dynamically binds abstract operations to executable Python code using `code_metadata.json`.
- **Output**: An Annotated Knowledge Graph containing validation reports (`dqv:QualityMeasurement`).

## Repository Structure

| Folder               | Description                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `executor/`          | Python implementation of the execution engine and `code_metadata.json`                     |
| `planner/`           | Python wrapper for the N3 reasoner and script generation                                   |
| `rules_n3_semantic/` | The core logic rules (N3) for generating validation plans (Timeliness, Completeness, etc.) |

## Usage

This repository is typically used as a submodule. To run tests directly:

```bash
# Install dependencies
pip install -r requirements.txt

# Run the semantic workflow test
python executor/test_semantic_workflow.py
```

## Extending the Engine

### Adding New Validation Logic
1.  **Define the Rule**: Add a new N3 rule in `rules_n3_semantic/` to map a high-level policy (e.g., `dqv:Accuracy`) to an abstract operation (e.g., `ab:CheckAccuracy`).
2.  **Define the Code**: Add the Python implementation signature in `executor/code_metadata_with_roles.json`.
3.  **Implement the Code**: Ensure the corresponding Python library/function is available in the executor environment.
